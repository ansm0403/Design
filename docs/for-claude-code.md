# Claude Code 시작 프롬프트

> 아래 텍스트를 Claude Code 세션 시작 시 그대로 붙여넣는다.
> 첨부할 파일: architecture.md, phases.md, mvp-checklist.md

---

## 붙여넣을 프롬프트 (검토 단계)

```
나는 디자인 시스템(디자인 토큰 + UI 컴포넌트 라이브러리)을 모노레포로
구축하려 한다. 함께 첨부한 3개 문서가 설계도다:
- architecture.md : 전체 구조·기술 스택·설계 원칙 (이 프로젝트의 헌법)
- phases.md       : Phase 0~5의 STEP별 상세 구현 지시
- mvp-checklist.md: 진행 추적 체크리스트

[1단계 — 검토만, 코드는 아직 작성하지 마라]
먼저 이 설계도를 너의 관점에서 비판적으로 검토해라:
1. 기술 스택의 버전·설정이 현재 시점에 유효한지 확인하라.
   특히 tsdown, Tailwind, Storybook, Vitest 의 최신 설치법과 권장 설정을
   확인하고, 문서의 내용과 다른 부분을 지적하라.
2. 설계상 빠졌거나 위험한 부분(순환 의존, 라이브러리 빌드 함정,
   peerDependency 처리, exports 경로 등)을 찾아 지적하라.
3. Phase 순서나 STEP 단위가 비합리적인 곳이 있으면 제안하라.
4. 단, 핵심 설계 원칙(토큰=CSS변수, 컴포넌트=Tailwind, 단방향 의존,
   핵심 컴포넌트 우선)은 유지한다. 이를 뒤집는 제안은 근거를 명확히.

검토 결과를 "유지할 것 / 수정 제안 / 추가 제안" 으로 정리해 보고하라.
내가 승인하면 다음 단계로 넘어간다.

[2단계 — 승인 후, 작업 문서 구성]
내가 검토 결과를 승인하면:
1. 보완 사항을 반영해 architecture.md / phases.md / mvp-checklist.md 를
   로컬에 갱신·정리하라.
2. 앞으로 작업하며 이 문서들을 살아있는 문서로 유지하라:
   - 설계 결정이 바뀌면 architecture.md 를 먼저 고치고 코드를 바꾼다.
   - STEP을 완료하면 mvp-checklist.md 를 체크하고 진행 로그를 남긴다.
   - 구현 중 알게 된 함정·노하우는 해당 phase 항목에 주석으로 추가한다.

[3단계 — 구현]
승인과 문서 정리가 끝나면 Phase 0의 STEP 0-1 부터 한 번에 하나씩 구현하라.
각 STEP(또는 관련 STEP 묶음) 완료 후 `edgecase-review` 스킬로 검증하라.
WARN/FAIL이 발견되면 `docs/edgecase/phase-{N}.md` 에 기록한 뒤 mvp-checklist를 체크하라.
그런 다음 멈추고 무엇을 했는지 요약한 뒤 내 확인을 기다려라.
한꺼번에 여러 Phase를 진행하지 마라. 나는 각 단계를 학습하며 따라간다.

[작업 원칙]
- 나는 React/TS 경험은 있으나 디자인 시스템·모노레포·pnpm 은 처음이다.
  중요한 개념은 코드에 주석으로 짧게 설명하라.
- 불확실한 최신 정보(버전·설정)는 단정하지 말고 확인 후 진행하라.
- 막히면 임의로 진행하지 말고 선택지를 제시하고 물어라.
```

## 사용 팁

- **1단계(검토)를 반드시 거치게 하라.** Claude Code가 최신 도구 정보로
  설계도의 약점을 잡아주는 단계다. 여기서 architecture.md 가 한 번 단단해진다.

- **승인 게이트를 지켜라.** "내가 승인하면 다음으로" 를 넣은 이유는,
  Claude Code가 검토→구현으로 폭주하지 않게 하기 위함. 각 단계를 학습하며
  따라가려는 본래 목적에 맞는다.

- **각 Phase 시작 시 컨텍스트 환기.** 새 세션이거나 대화가 길어지면,
  "phases.md 의 Phase N 부터 진행한다. architecture.md 원칙을 지켜라" 를
  다시 일러주면 일관성이 유지된다.

- **개념 질문은 나(설계 담당)에게.** 구현은 Claude Code, "이게 왜 이렇게
  동작하지?" 같은 개념 학습은 이쪽으로 가져오면 역할 분리가 깔끔하다.
